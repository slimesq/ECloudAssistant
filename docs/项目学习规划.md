# ECloudAssistant 项目学习规划

> 目标：理解并能够维护 ECloudAssistant 的界面、网络与信令、采集编解码、播放、远程输入及资源关闭，并与 ENET 完成统一的跨端验证。

## 1. 主线学习目标

完成本规划后，应能够独立做到：

1. 从 `main()` 追踪窗口创建、页面切换、登录通知和远程连接入口。
2. 解释 Qt 对象所有权、事件循环、signal/slot 与跨线程调用在项目中的作用。
3. 说明负载查询、登录服务切换、二进制包收发及信令初始化的路径。
4. 解释 Winsock、`select`、调度线程、连接和缓冲区的职责，以及一次读写如何推进。
5. 区分控制端与被控端的识别码、连接和状态，追踪一个输入事件到 Windows 执行。
6. 从屏幕图像和 PCM 追踪到 H.264/AAC，说明格式、时间基、编码配置及数据有效期。
7. 从 RTMP 连接、握手和命令追踪到发布应答、序列头与媒体发送。
8. 从 Packet 追踪到解码 Frame、队列、画面和声音，说明线程及资源交接。
9. 说明网络、采集、编码、解码与输出的停止路径，定位实际遇到的生命周期问题。
10. 将客户端入口与服务端处理对应起来，按 ENET [阶段十二](https://github.com/slimesq/ENET/blob/main/docs/项目学习规划.md#joint-validation)完成联合联调。

## 2. 项目边界与总体导航

## 4. 阶段零：工程与构建基线

配套讲义：[阶段零：工程与构建基线](阶段00_工程与构建基线学习讲义.md)。

### 目标与阅读顺序

1. [CMakeLists.txt](../CMakeLists.txt)：平台、C++17、模块依赖、源码收集与排除项。

3. [main.cpp](../main.cpp)、[res.qrc](../res.qrc)：程序入口、样式、图片与着色器资源。

### 构建与运行准备

在 Visual Studio x64 开发环境中确认 MSVC 和 Ninja 可用；当前预设要求 CMake 3.25 及以上。Qt 通过 `CMAKE_PREFIX_PATH` 定位，或在该值为空时使用环境变量 `QTDIR`。FFmpeg 使用 CMake 参数 `-DFFMPEG_ROOT=...`，或环境变量 `FFMPEG_HOME`、`FFMPEG_INCLUDE` / `FFMPEG_LIB`；当前代码不读取同名环境变量 `FFMPEG_ROOT`。具体配置与 DLL 准备见配套讲义。

```powershell
cmake --preset msvc-debug
cmake --build --preset msvc-debug
```

记下实际 Qt、FFmpeg、编译工具版本及构建结果。下文 Qt 资料为 Qt 6、FFmpeg 示例为 trunk 入口，查阅时切换到项目使用版本。

### 阅读重点

1. 哪些文件真正进入 `ECloudAssistant` 目标，哪些 `Net` 演示文件被排除？
2. Qt 和 FFmpeg 各链接哪些组件？头文件、导入库与运行时 DLL 分别从哪里取得？
3. x64、Ninja、Debug 和输出目录分别由工具链与预设的哪些设置确定？
4. 启动时哪些操作依赖外部服务？未初始化信令时退出，是否会访问空连接？

## 6. 阶段二：应用入口与 Qt 业务编排

配套讲义：[阶段二：应用入口与 Qt 业务编排](阶段02_应用入口与Qt业务编排学习讲义.md)。

### 本阶段先补什么

### 目标与阅读顺序

理解窗口、页面和业务对象怎样连接。本阶段跟到网络、媒体 API 的调用入口，内部实现留阶段四至八。

2. [ListInfoWgt.cpp](../UI/list/ListInfoWgt.cpp)、[MainWgt.cpp](../UI/center/MainWgt.cpp)：选择事件与页面切换。
3. [LoginWgt.cpp](../UI/center/LoginWgt.cpp)、[RemoteWgt.cpp](../UI/center/RemoteWgt.cpp)、[RemoteManager.cpp](../UI/center/RemoteManager.cpp)：登录通知和远程入口。
4. 最后按需要看 `TitleWgt/CustomWgt/ListWidget/StyleLoader` 与资源文件；着色器的绘制原理留阶段八。

### 核心链路

```text
main → ECloudAssistant → MainWgt
  ├─ 创建 LoginWgt：构造时已经尝试连接负载
  ├─ 创建 RemoteWgt → RemoteManager
  │   ├─ 基类 RtmpPushManager → EventLoop(1)
  │   └─ RemoteManager 自身 → EventLoop(2)
  └─ 默认显示 remoteWgt

侧栏选择 → sig_Select → slot_ItemCliked → 页面切换
登录成功 → sig_logined → handleLogined → RemoteManager::Init
开始远程按钮 → RemoteManager::StartRemote
```

### 阅读重点

1. 三个界面区域由谁创建？parent 与智能指针分别管理哪些对象？
2. 为什么默认显示远程页面，登录页构造时却已经联网？
3. `RemoteManager` 和网络调度线程是在创建窗口、登录成功还是点击远程时建立？
4. 本机识别码与目标识别码分别来自哪里，进入哪个业务 API？
5. 哪些页面已有业务，哪些是占位？样式、图片和着色器怎样从资源系统加载？

### 练习与验收

## 7. 阶段三：Qt 登录链与二进制协议

配套讲义：[阶段三：Qt 登录链与二进制协议](阶段03_Qt登录链与二进制协议学习讲义.md)。

### 本阶段先补什么

TCP 知识直接复用，补 `QTcpSocket` 连接、`readyRead`、阻塞等待和接收缓冲的用法。先对照项目收发路径，API 仍不清楚时再看现成 Qt 示例；示例的 `QDataStream` 与项目自定义包分别理解。

### 目标与阅读顺序

理解负载查询、登录服务切换及响应处理，跟到被控端信令初始化 API 为止。

1. [defin.h](../UI/tool/defin.h)：`packet_head/Login_Info/LoginReply/UserLogin/LoginResult`。
2. [LoginWgt.h](../UI/center/LoginWgt.h)、[LoginWgt.cpp](../UI/center/LoginWgt.cpp)：socket、状态标志及收发入口。
3. [RemoteWgt::handleLogined](../UI/center/RemoteWgt.cpp)、[RemoteManager::Init](../UI/center/RemoteManager.cpp)：响应如何交给业务对象。

### 核心链路

```text
构造时连接负载 → Login_Info → 负载服务
登录按钮 → 向当前 socket 发送 Login_Info
readyRead → ReadData → HandleMessage → HandleLogin
  → is_login_ 为 false：HandleLoadLogin
  → 切换到登录服务 → UserLogin

再次 readyRead → HandleLogin
  → is_login_ 为 true 且成功：sig_logined
  → handleLogined → RemoteManager::Init
```

### 阅读重点

1. 两种响应都使用 `Login` 命令时，代码靠什么区分 `LoginReply/LoginResult`？
2. 当前 socket 连接负载还是登录服务？再次点击登录按钮会向谁发送什么？
3. `len/cmd`、结构体布局、字节序和字符串边界是什么约定？
4. `readAll()` 是否保证完整消息？拆开的包头、半包或两个包一起到达时，当前代码会怎样处理？
5. 账户、密码与固定登录码 `345` 怎样进入 `UserLogin`？界面注册入口和服务端实际校验分别实现到了哪里？

当前 `HandleRegister()` 为空；服务端主要按识别码查询并检查在线状态，未校验请求中的账号、密码。数据库和账号删除内部按 ENET 阶段六学习。

### 练习与验收

有服务和调试条件时，用日志或一个断点跟一条响应；条件不足时，按讲义中的 `LoginResult` 样例推演分片与尾部，也可复用 ENET 已有样例。实际用到的协议差异补入共同记录。

```text
连接：TcpConnection::Close / 析构 → 核对事件移除入口与 socket 关闭位置
```

这是当前源码的调用顺序，不代表已经满足安全释放条件。沿这些入口核对实际调用和对象存活；队列、排队重绘、事件注销与外层析构还需继续追踪。

### 阅读重点

1. 先关闭发布连接、再等待编码线程时，工作线程是否还会访问 `pusher_`？采集线程何时结束？
2. `AVPlayer::Close()` 在线程尚未创建时是否安全？GUI、信令回调与析构触发关闭时，调用线程有何不同？
3. `quit_/stop_/exit_`、队列状态及对象指针由哪些线程读写？锁或原子保护覆盖了什么？
4. 阻塞读流怎样通过中断回调结束？解码线程、Frame 队列与 queued 重绘还需要哪些对象存活？
5. `EventLoop*`、`AVContext*`、音频设备和 OpenGL 资源最终由谁释放？再次启动时是否重置退出标志与线程对象？

### 练习与验收

先按源码跟一遍推流停止、播放停止与网络退出，指出每次等待的目标线程及其仍需使用的对象。有现成运行条件时，复用一次正常停止和一个实际遇到的未连接、取消或读流结束场景，用断点或已有日志核对；没有时按调用顺序推演，不额外搭服务或制造全部失败分支。

- [ ] 能分别说明采编、播放和网络的停止入口及关键等待顺序。
- [ ] 能指出关闭过程中仍可能被线程或回调使用的对象。
- [ ] 能区分窗口消失、线程退出与资源释放，解释未开始、失败、重复停止及再次启动的边界。

## 14. 阶段十：客户端与服务端接口对照

配套讲义：[阶段十：客户端与服务端接口对照](阶段10_客户端与服务端接口对照学习讲义.md)。

### 本阶段先补什么

在客户端阶段零至九之后进行，复用两端已有基础与源码结果。此处先做静态对照，完整动态验证在 ENET 阶段十二进行。

### 目标与阅读顺序

把请求、响应、流地址、媒体与输入的生产和消费入口对应起来。

1. [LoginWgt.cpp](../UI/center/LoginWgt.cpp)：对照 ENET 负载、登录服务的地址切换与响应。
2. [客户端 SigConnection](../Net/SigConnection.cpp)：对照服务端登记、获取流、建流回复、播放和输入转发。
3. [RtmpPublisher.cpp](../Pusher/rtmp/RtmpPublisher.cpp)、[RtmpConnection.cpp](../Pusher/rtmp/RtmpConnection.cpp)：对照服务端发布状态、流路径与媒体类型。
4. [AVDEMuxer.cpp](../Codec/AVDEMuxer.cpp)、[AVPlayer.cpp](../Puller/UI/AVPlayer.cpp)：播放 URL、画面声音输出及输入包产生位置。

### 核心链路

```text
登录响应 → 初始化本机信令
控制端请求目标 → 服务端通知被控端建流
被控端启动发布并回复流地址 → 服务端通知控制端播放
控制端拉流并发送输入 → 服务端转发 → 被控端执行
```

### 阅读重点

1. 登录、两种信令角色、RTMP 发布与 FFmpeg 拉流各用哪条连接，地址由哪里取得？
2. 登录码、本机识别码、远程目标和控制连接注册码分别怎样使用？
3. 建流成功回复时 RTMP 走到了哪一步？发布应答与首帧在哪里确认？
4. 哪些包由服务端解析，哪些只透明转发？声明差异是否进入实际解码路径？
5. 黑屏、无声、输入无效或关闭未结束时，应先定位哪个生产、转发或消费入口？

### 练习与验收

沿一轮建流交互和一条输入消息，定位两端发送、转发、消费函数；核对当前用到的字段和配置，已有协议结果直接复用。负载入口当前为 `192.168.31.30:8523`，还需核对 RTMP 地址、采集参数及两端实际代码版本。

- [ ] 能区分源码已确认的行为与尚待实测的结果。
- [ ] 已按共享配置说明核对登录码、识别码和目标，随后进入联合联调。
